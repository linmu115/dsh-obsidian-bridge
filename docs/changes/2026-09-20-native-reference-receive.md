# 独立实例接收 Obsidian 引用

Bridge 0.4.1-rc2.7 修正未接入 Maintenance 时的引用接收路径。

旧客户端对本地会话也请求 `/dsh-session-maintenance/api`，只在 404 时认为该接口不存在。DSH 0.1.5-rc.2 的未注册 POST 路由实际返回 405，导致接收抛错。

宿主现在通过 Bridge 配置明确声明是否注册了可选会话解析服务。客户端收到能力缺席声明时直接使用当前本地会话；不会探测不存在的维护接口。服务存在时仍执行解析且保留失败保护；携带逻辑会话身份的历史目标在缺少解析能力时明确报错，不猜测本地映射。旧宿主未声明能力时保留原兼容行为。

更新安装后需要刷新已打开的 DSH WebUI，包括 Obsidian 内的 Web Viewer。引用待接收队列不因升级而删除。

相关 17 项测试、类型检查与构建通过。真实部署后，用户刷新 Obsidian 内网页，确认引用气泡出现且会话测试正常；随后核验同一引用为 claimed，并存在同步回执，等待接收数量为 0。无会话时仍保留队列等待，不自动创建或选择目标会话；本次成功不覆盖该分支或其他插件全功能。
